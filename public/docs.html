Forme Fit API

Size recommendations from one portable shopper profile. JSON over HTTPS. The machine-readable spec is at /openapi.json.

Authentication

Send your key as Authorization: Bearer <key>. Create keys under Console → Integration.

  • pk_live_… publishable keys can be embedded in web pages and apps. They can recommend sizes, manage the shopper's own profile, read size charts and track events. Restrict them to your domains with allowed origins. Once origins are set, requests without an Origin header (servers, mobile apps) are refused for that key: use a secret key, or a second publishable key without origins, for apps.
  • sk_live_… secret keys are for your servers only: catalog sync and return feedback. Requests that carry a secret key from a browser are rejected.

Errors and limits

Errors use HTTP status codes with a body of {"error":{"code","message","details?"}}. Each key may make 600 requests per minute; the remaining budget is in X-RateLimit-Remaining.

{ "error": { "code": "product_not_found", "message": "No product with SKU X. Sync it with PUT /v1/products/{sku}." } }

Typical integration

  1. Your server syncs products: POST /v1/products/bulk nightly, or PUT /v1/products/{sku} on change.
  2. The storefront loads widget.js with a publishable key, or calls /v1/profiles and /v1/recommend from your own UI.
  3. Track add_to_cart and purchase with the rec_id you received.
  4. Your returns system posts outcomes to /v1/feedback. Forme recalibrates products that run small or large.
